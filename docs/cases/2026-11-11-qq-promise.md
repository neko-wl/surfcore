# QQ：承诺定时（她说了几点，就一定按时来）

日期：2026-11-11
版本：待定（dev）
相关：`src/promise-time.mjs`、`src/bridge.js`、`src/mcp-snowluma-safe.js`、`config.example.json`

## 现象

她在私聊里说「那我今晚十一点半来找你」，还写进了收尾记录。23:30 什么都没有。

第一版修法是「配置里手写一个时刻」（见 [定点主动](2026-11-10-qq-scheduled-proactive.md)），
但那只解决了「用户预先知道要定几点」的情况。真正的要求是：

> 她在聊天里承诺几点，系统就要在**那之前 10 分钟内随机一刻**主动来找，把这个承诺兑现掉。

关键是「承诺」本身得进系统——配置解决不了，因为时刻是她在对话里随口说出来的。

## 根因

一层是能力缺失，一层是责任缺失：

1. **能力缺失**：`[目的]` 吃 `dailyMax` + 安静时段；`[主动机会]` 是 30~90 分钟随机 + 概率，夜里再 ×0.3。
   两者都不提供「在某个具体时刻附近必发」。
2. **责任缺失**：就算有定时器，也没人负责把「她刚才那句『十一点半来找你』」翻译成一条待办。
   模型说完那句话就结束了，那句话只留在对话历史和收尾摘要里，没有任何结构化字段。

## 修法

两条入口同时上，**工具优先、扫描兜底**：

### 1. 工具 `qq_set_promise`（精确）

```json
{ "key": "private:40722995", "token": "...", "time": "23:30",
  "text": "今晚十一点半来找你" }
```

- 桥接新增 `POST /api/socialV2/promise`（reserved2 + agent token + 白名单校验，与其它 v2 写接口一致）；
- 时间只认 24 小时制 `HH:MM`；已经过去的时刻**顺延到明天**（否则 23:31 登记 23:30 会变成「已过期」）；
- 取消：`cancel: true`（可带 `id` 精确取消）。

工具描述里明确写了「只要答应了具体时间点就必须在同一轮调用」。模型会读描述。

### 2. 出站扫描（兜底）

`recordSentMessagesV2()` 是每条出站消息的必经钩子。在它后面挂 `notePromiseFromOutbound()`：

```
她发出的话 → 有「约」的语气？ → 认得出钟点？ → 不是过去/习惯叙述？ → 登记
```

这样**她忘调工具也不会漏**。代价是可能误报，所以判定刻意保守（见下表）。

### 3. 调度：在 [约定-10 分钟, 约定] 里随机

```
forAt   = 约定的时刻
fileAt  = forAt - leadMs + random() * leadMs      // leadMs 默认 600000（10 分钟）
```

30 秒心跳（与定点主动共用），到 `fireAt` 就唤醒，原因 `promise:<id>`。
唤醒词是【赴约】，明确要求**不要提「定时」「提醒」「系统」**——要像她自己记着这件事，
否则每句话都带着机械味。

## 完整逻辑

### 1. 链路

`registerPromiseV2()` 写 `st.promises[]` → `saveSocialV2State()` 落盘 → 30 秒 tick `runPromiseTick()`
→ `sendWakePromptV2(key, 'promise:<id>')` → DSH 会话 → QQ。

入口两个：MCP 工具 `qq_set_promise`（→ HTTP 路由）和 `recordSentMessagesV2` 里的扫描。
两者最终都汇到 `registerPromiseV2`，所以去重、窗口、落盘只有一份实现。

### 2. 机制

纯判定在 `src/promise-time.mjs`（可单测），桥接只负责状态与投递。刻意保守：

| 会登记 | 不会登记 | 为什么 |
| --- | --- | --- |
| 「今晚十一点半来找你」 | 「我十点就睡了」 | 没有「约」的语气 |
| 「明天九点喊你起床」 | 「昨天十一点半聊到很晚」 | 过去的事 |
| 「23:30 见」里的钟点 | 「晚一点来找你」 | 没有具体钟点 |
| 「晚上八点提醒你」 | 「晚一点」里的「一点」 | 「一点」是副词不是钟点 |

两个实测踩到的坑（都已写进测试）：

- `晚/早/快/慢/少 + 一点` 里的「一点」不是钟点；但 **「今晚十一**点**」里的「一点」是**——
  只能对「恰好是单字『一』」做副词排除，否则「今晚十一点半」会被前一个字「晚」误杀。
- `二十三` 这类数字，字符类里**必须同时有「二」和「两」**（我第一版把「二」替换成了「两」，
  结果 `二十三` 直接解析成 null）。

### 3. 爆炸半径

桥接进程 1 个。新增 state 字段 `promises`（最多 20 条，已进 `saveSocialV2State` 白名单）。
默认 `promise.enabled: true` 但只有**真的出现约定**才会产生条目——不会凭空多说话。
扫描只在 `recordSentMessagesV2` 里跑，纯字符串判断，无网络。

### 4. 取舍

| 路线 | 收益 | 代价 |
| --- | --- | --- |
| **工具 + 扫描**（选） | 精确 + 兜底；她忘调也不会漏 | 两套入口，需要去重；扫描有误报风险 |
| 只做工具 | 最干净 | 她忘了调就整条链断——正是本次事故的形态 |
| 只做扫描 | 完全自动 | 中文时间表达必然误报，且无法取消 |

### 5. 生效与重启

改代码后重启桥接进程；`config.json` 的 `socialV2.promise` 可选（不配就是默认值）。
DSH 侧要重启才会重新读取工具清单（`qq_set_promise` 是新工具）。

### 6. 验证

```bash
node scripts/test-qq-promise.mjs     # 13 个用例：解析 / 窗口 / 登记 / 幂等 / 错过 / 取消 / 扫描 / 失败路径
node scripts/test-scheduled-proactive.mjs
node scripts/test-audit-regressions.mjs
node scripts/test-audit.mjs
```

线上：日志出现 `[承诺] 登记 private:xxx 约定 23:30（tool · …）→ 将在 23:2x 左右唤醒`，
到点出现 `[承诺] 到点赴约 private:xxx：约定 23:30（tool），现在 23:2x 叫醒`。

### 7. 回滚与残余

- 回滚：`socialV2.promise.enabled = false` 并重启；代码层无迁移。
- 残余：扫描只处理**当天 24 小时内**的口头约定；跨天（「下周三」）只能靠工具显式登记。
- 残余：「23:30 见」这种没有「约」字的口语不会命中扫描（`见` 单字太容易误报），
  仍要靠工具登记。

## 反向：对方答应来找她（等不到人就问）

上面那节是「她要来」，还有对称的一种：「**他**说要来，她等；等不到就主动问」。
两个方向的时刻语义完全不同，所以用 `direction` 分开存：

| | out（她要来） | in（他要来） |
| --- | --- | --- |
| 触发点 | `fireAt` = 随机落在 `[T-10min, T]` | `askAt` = 随机落在 `[T+10min, T+20min]` |
| 动作 | 主动去找对方（【赴约】） | 等对方；没人来就问一句（【没等到人】） |
| 判定「来了」 | —— | `st.lastIncomingAt >= T`（约定时刻之后收到过任何入站消息） |

用 `lastIncomingAt` 而不是翻 `recentMessages`：后者有 100 条上限，翻旧账会翻不到，
而「约定之后有没有人说话」本质上就是「最后一次入站时间晚于约定时刻」。

状态机多了两个终点：

- `kept` —— 他如约出现，不需要追问（**要记下来**，不能静默跳过，否则排查时看不出到底是没触发还是被跳过）；
- 追问也有 `noshowGraceMs`（默认 2 小时）兜底，超了就 `missed`，不会半夜三点补一句「你不是说十点半吗」。

入站识别同样保守，且和出站用**两套不同的词表**：

| 会登记 | 不会登记 |
| --- | --- |
| 我今晚十一点半来找你 | 今晚十一点半（没说谁来） |
| 等我十一点半 | 我十点就睡了（不是来赴约） |
| 我这就过来（十点半） | 我去睡了，晚安（只是去睡觉） |

群里只在主人说话时登记——别人一句「我一会儿过来」不该让她整点去催。

## 第三种：模糊承诺（「晚点」「稍后」）

「今晚 11:30」能算出一个时刻，「晚点找你」算不出来——但它同样是承诺。这类走另一套规则：

| | 精确承诺 | 模糊承诺 |
| --- | --- | --- |
| 时刻 | 由「几点」算出 | **没有**，只有「从说这句话起」 |
| 触发 | `[T-lead, T]` 或 `[T+miss, T+miss+ask]` | `[createdAt+1h, createdAt+2h]` 随机 |
| 额外条件 | —— | **期间没再聊过**才触发 |

「期间没聊天」和反向承诺共用同一个事实：`st.lastIncomingAt > p.createdAt`。
登记之后只要收到过一条入站消息，就说明这段对话还活着，不需要她再主动。

两个方向对称：

- 她说了「先去忙，晚点找你」→ 1~2 小时后一直没聊，她回来把这句话接上（【接上】）；
- 他说了「我晚点回来」→ 1~2 小时后还没动静，她主动问一句（【没等到】）。

边界：

- **带具体钟点的句子不走这条路**（`晚点十一点半来找你` 会被当成精确承诺）——
  否则「1~2 小时」的模糊窗口会把一个明确的约定降级；
- 必须跟「联系你」的动词：`早点睡`、`一会儿就凉了` 不登记；
- 超时兜底 `vagueMaxMs + noshowGraceMs`（默认 2h + 2h），过期记 `missed`。

## 影响面

- 只新增三条主动路径（赴约 / 追问 / 模糊），都是承诺状态机的分支；不改 `[目的]` / `[主动机会]` 的任何行为。
- 同一方向、同一时刻 5 分钟内只留一条（工具与扫描同时命中同一句话时不会双发）。
- 失败可见：过期 → `[承诺] 错过 …` / `[承诺] 放弃追问 …`；如约出现 → `[承诺] 如约出现 …`；
  唤醒异常 → `[承诺] 唤醒异常 …` + `st.lastPromiseError`（含 hint）；
  工具登记失败返回 `code` + `error` + `hint`（如 `promise.bad-time` / `promise.past` / `promise.tool-disabled`）。
